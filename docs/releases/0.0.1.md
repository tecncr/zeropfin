First alpha of Zeropfin, a Jellyfin playback receiver for the Raspberry Pi 1 Model B (256 MiB)
and Pi Zero / Zero W on a composite CRT, controlled from a phone browser.

> **Alpha. Not yet tested on Raspberry Pi hardware.** Every automated test ran on x86_64 with a
> mock player and a fake Jellyfin, or under qemu emulating the Pi 1's ARM1176 CPU. Please report
> results using the checklist in `/usr/share/doc/zeropfin/hardware-test-report.md`.

## Install (Raspberry Pi OS Lite 32-bit, Trixie)
```sh
unzip zeropfin-0.0.1-armhf.zip && cd zeropfin-0.0.1
sudo ./setup.sh                      # apt installs the .deb and its runtime dependencies
sudo -u zeropfin zeropfin setup        # Jellyfin URL + account; only a token is stored
```
Then open `http://<pi>.local:8080/` on your phone and pair. Nothing is compiled on the Pi.

## Assets
- `zeropfin-0.0.1-armhf.zip`: `setup.sh`, `INSTALL.md`, checksums and the `.deb`.
- `zeropfin_0.0.1_armhf.deb`: the same package on its own (`sudo apt install ./zeropfin_0.0.1_armhf.deb`).
  - Contents: the ARMv6 daemon, the web remote, a systemd unit, and the patched ZeroPlay at
    `/usr/lib/zeropfin/zeroplay`.
  - It declares all runtime dependencies (libmicrohttpd, libcurl, cJSON, FFmpeg, libdrm, ALSA,
    FreeType), as computed by `dpkg-shlibdeps`.
- `SHA256SUMS`.

## What works (in automated tests)
- **Library:** browse, search, continue watching, next up, latest, and series/seasons/episodes
  with artwork.
- **Playback control:** play, resume, pause, seek and stop via the bundled ZeroPlay; position is
  labelled "verified" or "estimated"; the player restarts itself after a crash.
- **Jellyfin reporting:** playback start, progress and stop are reported; finished items are
  marked played; a crash is never reported as finished.
- **Direct play only:** H.264 8-bit up to 1080p30 / level 4.1 / 12 Mbps, with the first audio
  track in AAC/MP3/AC3/FLAC/Opus. Anything else is refused with a reason.
- **Security:** authenticated loopback media relay, so the token is never in a URL; one-time
  pairing codes (on the TV or over SSH); CSRF, Origin and Host checks; LAN-only by default.

## Known limitations
- No transcoding, no audio-track selection, and no external subtitles. The first embedded text
  subtitle track is always shown.
- Plain HTTP on the LAN.
- Not a Jellyfin cast target: the official apps can't control it.
